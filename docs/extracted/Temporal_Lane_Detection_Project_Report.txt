1. Executive Summary
This project builds a camera-based lane perception module for an autonomous vehicle or ADAS prototype. The
system reads a forward-facing road video, detects the left and right lane boundaries, uses recent frames to reduce
temporary loss of a lane, estimates a reliability score, and outputs lane geometry that a later path-planning module
could consume.
Final problem in one sentence
Single-frame lane detectors can become fragmented or unstable when markings are faded, broken,
shadowed or briefly hidden; the proposed model uses short-term video memory and confidence estimation
to provide more stable, honest lane predictions.

2. Problem Definition and Motivation
Lane perception is a basic input to lane keeping, path planning and driver-assistance systems. In clean daytime
highway scenes, painted lanes are usually visible. Real roads are more difficult: paint fades, markings break,
shadows resemble lines, vehicles cover parts of the lane, glare reduces contrast, and curves change the apparent
shape.
Observed failure chain
Lane becomes unclear
Single-frame model loses
 evidence
Prediction breaks or jumps
Planner receives unstable
 geometry
Research problem statement
 Formal statement
Existing lane-detection systems often process frames independently and may produce fragmented,
flickering or incorrect lane boundaries when lane evidence is degraded or temporarily occluded. The project
investigates whether a lightweight temporal memory mechanism can improve lane continuity and stability
while preserving real-time speed, and whether calibrated confidence can identify predictions that should not
be trusted.
Scope boundaries
●
 Primary target: faded, broken and temporarily occluded painted lane markings.
●
 Conditions: normal, curve, shadow, night/low light, crowded traffic and wet-road visibility where data is available.
●
 Input: monocular RGB video from a front-facing camera.
●
 Output: lane mask or lane points, fitted left/right curves, lane centre, curvature, vehicle offset estimate and
confidence.
●
 Out of initial scope: completely unmarked roads with no defensible lane ground truth, real-vehicle actuation,
LiDAR/radar fusion, and legal safety certification.
Plain-language explanation
A human driver does not forget a lane merely because another vehicle hides it for one second. The proposed
model similarly keeps a short memory of recent frames. It should continue a lane only when recent visual evidence
supports it, and lower its confidence when the estimate becomes uncertain.

5. Proposed Technical Architecture
Camera video
Frame sequence
Shared encoder
ConvGRU
 memory
Lane decoder
Geometry +
confidence
5.1 Frame sequence
The loader supplies a short ordered sequence such as frames t-2, t-1 and t. Frames must come from the same
video and remain in time order.
5.2 Shared visual encoder
A lightweight convolutional encoder extracts road textures, edges, curves and lane-marking features from each
frame. The recommended practical route is to reuse the encoder and lane head of an open-source lightweight
baseline rather than inventing an entire network before the pipeline works.
5.3 Temporal memory
A ConvGRU receives current visual features and the hidden state from recent frames. It updates memory spatially,
preserving useful lane evidence while allowing the state to change as the road curves. It is inserted at a reduced
feature resolution to control compute cost.
5.4 Lane decoder
The decoder upsamples the temporally enhanced feature map into a lane probability mask. A threshold converts
probabilities into a binary mask; post-processing then extracts lane components and points.
5.5 Geometry and reliability
Lane points are fitted with a polynomial or spline to generate left/right curves. The system estimates lane centre,
approximate curvature and lateral image offset. Reliability combines calibrated lane probability, continuity and
agreement with recent frames. A low score tells the downstream module not to rely blindly on the output.
Operational rule
The model may bridge a short temporary occlusion when recent evidence is strong. It must not indefinitely
hallucinate a lane after evidence disappears. Memory reset and confidence decay are therefore required.

8. Training Design
Training begins only after the baseline inference and metrics are verified. The first experiment should freeze or
partially freeze the pretrained encoder, train the temporal module and decoder, then gradually unfreeze layers if
necessary.
Input and augmentation
●
 Input size: start with the baseline's native resolution (commonly around 640-wide) rather than arbitrary resizing.
●
 Sequence length: begin with 3 frames; compare 1, 3 and 5 in an ablation.
●
 Apply the same geometric augmentation to every frame and mask in a sequence.
●
 Use brightness, contrast, blur, shadow and limited rain-like augmentation carefully; keep an untouched real test
set.
●
 Do not reverse time or randomly shuffle frames inside a sequence.

selected on validation data and reported. The paper should include an ablation showing the effect of each

Confidence behavior
●
 High: strong lane probability, continuous curve and agreement with recent frames.
●
 Medium: partial visibility or short temporal interpolation; usable only with caution.
●
 Low: weak evidence, inconsistent geometry or memory too old; downstream module receives an unreliable flag.
●
 No lane: no defensible estimate; the research prototype reports failure instead of inventing a path.
Safety disclaimer
In the student prototype, a low-confidence output should trigger only a displayed/logged warning or
simulator behavior. Real braking, steering or driver-handover logic requires separate safety engineering and
validation.
